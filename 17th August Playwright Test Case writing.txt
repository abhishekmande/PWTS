1.Inside this playwright.config.ts file we have mentioned that test-file will be created inside "./test" folder under testDir:'./tests',
	so inside the tests folder we write the test file:"example.spec.ts" and inside the test file there are different test-cases, below is the example of a test-file: example.spec.ts and inside it test-case:
	
	import { test, expect } from '@playwright/test';
	
	test('get started link', async ({ page }) => {
		await page.goto('https://playwright.dev/');

		// Click the get started link.
		await page.getByRole('link', { name: 'Get started' }).click();

		// Expects page to have a heading with the name of Installation.
		await expect(page.getByRole('heading', { name: 'Installation' })).toBeVisible();
	});

//IMPORTANT: WHAT IS THIS async-await WRITTEN INSIDE TEST-CASE		   
-> JS and TS are aysnchronous in nature ie parallel execution and not synchronous ie sequential execution,
	but when we write the normal JS and TS code so every line of code executed sequentially and not paralley,here JS and TS has the natural ability of convertng the parallel execution of lines of code into sequential order that is why every line of normal js and ts code execute sequentially,
	but when JS and TS code is integrated with 3rd party tool like playwright then JS and TS natural ability of converting the execution of line of code from parallel to sequential doesnt not work and the lines of code execute parallely which can cause error,
	so to solve the problem of JS anf TS code integrated with PLaywright code which causes parallel execution we use async-await for sequential execution of lines of code, 
	so both "async" and "await" go together ie if we only write async and no await then it will not work or we write await but no async then also it will cause error
	so whenever we define a function we write async beside the () and inside {} we write await for each line of code inside the {} so below wg:
	
	/*
	import { test, expect } from '@playwright/test';
	
	test("Title", async function({page})=>
		{
			await page.goto("https://practicetestautomation.com/practice-test-login/")
			await page.locator("#username").fill("student")
			await page.locator("#password").fill("Password123")
			await page.locator("#submit").click()
			await expect(page.getByText("Log out", {exact: true})).toBeVisible()
	})
	
	*/
	
	NOTE: await is not to wait for an element to display on the page, await is making sure that the
		  that the step or line of code should be complete before it moves to the next line of code
		  so if the line of code is sucess then go to next line of code, and if the line of code is not sucess then the test case fails,
		  Q. but now the question is how does the await knows the line of code is success or fail?
		  -> so whenever in the line of code we are using actions ie methods() such as goto(), fill(), click(), toBeVisible() all
				method having common in them is they returns a action through Promise<>, so the await waits for the Promise<> to notify the await wether the method integrated in each line of code return either pending,sucess, rejected
				
				Promise is an object- which notifies different action ie pending, sucessfull, rejected
